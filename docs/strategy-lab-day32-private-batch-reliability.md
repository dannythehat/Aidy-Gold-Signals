This is the laboratory's PRIVATE research scheduler, not a public customer bot launcher, a real XAUUSD profitability tester, GoldThinker paper trading or the Elite 20 master account.

## Actually implemented

- `src/aidy/strategy_lab_batch_queue.py`: durable local SQLite in WAL + FULL-sync transactions and **BEGIN IMMEDIATE** for globally atomic queue state; stable content-addressed job fingerprint with original strategy rule SHA, market source SHA, chosen timeframe, predeclared immutable bounded typed parameters, experiment family ID and explicit synthetic-only stage. Identical submissions return same immutable job, not duplicate work, while changed source/rules/timeframe create a new trial and therefore count towards the experiment family. There is no user-supplied arbitrary executable function or downloaded strategy code in the queue.
- **Quotas** are fixed deterministic fail-closed engineering policy: maximum **100 nonterminal queued+running**, **four** parallel active worker leases across all families, **two** per trial family, maximum **three** crash/failure attempts per job, and **60,000 ms** lease lifetime. The main job-ID+family SQL index and `BEGIN IMMEDIATE` protect against simultaneous duplicate claims. Lease tokens fence stale workers after crashes, even with the same job number. Surviving tasks are recovered on restart, fail to DEAD if exhausted, and make durable experiment results available for compare.
- `events` is an append-only **source-hashed job lifecycle evidence chain**; source/result hashes and fixed synthetic-only status accompany all comparison rows. Each comparison can be restricted by a *declared family* and sorted by diagnostic score with stable hash tie-breaks. This IS NOT a statistically validated trading metric, a true economic strategy ranking, an AIDY nine-factor score, a broker execution record or a GoldThinker marketable strategy page.
- `scripts/strategy_lab/day32_100_job_acceptance.py` submits EXACTLY 100 independently keyed SYNTHETIC strategy hypotheses spanning 10 original families and two chart timeframes. It checks 20 repeat submissions produce no duplicate slots, deliberately attempts 101st nonterminal job and blocks it, claims all four available workers and blocks the fifth, kills/reopens SQLite with 4 uncompleted claims, recovers expired leases, rejects all four stale-worker finish attempts, injects 6 recoverable synthetic execution failures, reconnects multiple times during processing, and drives all **100 through successful unique completion** with zero DEAD/pending/running. It compares all 100 result/source SHA and independently replays the complete suite against a fresh database to detect run-to-run inconsistencies. Saved complete result rows in `artifacts/strategy_lab/day32_100_synthetic_results.json`, plus `day32_batch_queue_acceptance.json` with full quota measurements, hash-chain tip, unique completion count and explicit absence of real XAUUSD trading profit.
- `tests/test_strategy_lab_batch_queue.py` probes source/control injection, malformed hashes, changing rule versions, duplicate family/timeframe, frozen quota, independent two-connection atomicity, worker fencing, expired lease, 3-attempt dead lettering, forged real-money profit fields, negative/malformed results, immutable success, compare corruption and altered event chain. Original engine Days24–31 regression suite remains separately unmodified.
- `.github/workflows/strategy-lab-day32-batches.yml` runs strict Ruff and compilation, all queue unit tests plus relevant locked prior regressions, and *executes both full synthetic 100-job runs in actual CI*, requiring exact 100/100 completion, twenty duplicate declines, four stale completion refusals, six recovered faults, no quotas exceeded and both acceptance artefacts uploaded.
